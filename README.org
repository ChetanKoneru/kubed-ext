#+TITLE: kubed-ext
#+OPTIONS: toc:2

* Modular Kubernetes workflows

=kubed-ext= adds isolated asynchronous resource tables, Stern logs, metrics,
scoped actions and terminals to [[https://github.com/eshelyaron/kubed][Kubed]]. Native Kubed remains the base client.
This is not complete k9s parity. See the [[file:docs/superpowers/verification/2026-11-14-modular-kubernetes-client.md][verification and compatibility report]]
for measured results and remaining gaps.

* Dependencies and loading

- Emacs 29.1+, Kubed 0.7.1, Transient 0.4+. Validation uses the running Emacs
  31.1 server and installed Kubed 0.7.1; minimum-version execution is not tested.
- =kubectl= for cluster operations; Stern for advanced streaming logs.
- Optional terminal backends: vterm, eat, Ghostel. Built-in eshell/ansi-term
  adapters are also available. Kubel is not required or uninstalled by us.

** Install with =use-package :vc=

On Emacs 30+, the built-in =use-package= supports =:vc= installation from Git.
On Emacs 29.1, use a version of =use-package= with =:vc= support, or use the
manual loading example below. Install =kubectl= and =stern= separately and
make sure they are available in Emacs's =exec-path=.

#+begin_src emacs-lisp
(use-package kubed
  :vc (:url "https://github.com/eshelyaron/kubed")
  :demand t
  :bind-keymap ("C-c k" . kubed-prefix-map))

(use-package kubed-ext
  :vc (:url "https://github.com/CsBigDataHub/kubed-ext")
  :after kubed
  :demand t
  :custom
  (kubed-ext-stern-program "stern")
  (kubed-ext-crd-discovery-enabled t)
  (kubed-ext-resource-display-limit 1000)
  (kubed-ext-log-retention-characters 200000))
#+end_src

Loading =kubed-ext= installs its integration automatically; no additional
=:config (kubed-ext-setup)= is needed. Start with
=M-x kubed-ext-list-resources=, or open a native Kubed list and press =?=.
The =:vc= declarations install the repository's published default branch;
uncommitted changes in this working tree are not included.

** Load a local checkout

Add the source repository to =load-path=. The normal entry point is
=require 'kubed-ext=. Loading the entry automatically runs the idempotent
=kubed-ext-setup=. During development explicitly select source: a pre-existing
untracked =kubed-ext.elc= is stale and has deliberately not been changed.

#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/kubed-ext")
(require 'kubed-ext "kubed-ext.el")
#+end_src

If the feature is already loaded, explicitly reload =kubed-ext.el= with
=load= and its full =.el= filename. Changed dependency modules must also be
source-reloaded; =require= does not reload features already present.

** Tests

The five ERT suites live in =tests/=. For development, add both the repository
root and its =tests/= directory to =load-path= before loading the suites.
The extra directory lets review regressions require the shared core test helpers.
Run ERT in the existing Emacs session with =M-x ert=; test names start with
=kubed-ext-=. When reusing a development session, select tests from current
source files rather than obsolete tests left registered by earlier revisions.

* Native and enhanced keys

Setup changes only =?= in native =kubed-list-mode-map=. Native =g= refresh,
=RET= resource selection, =/= filter, =d= mark-for-deletion, =u= unmark,
=x= delete-marked, =D= delete, =e= edit, =!= kubectl command, =w= copy,
and =+= create remain upstream Kubed commands. Native marking and caches are
not replaced by enhanced ones. =?= also opens the menu in enhanced tables,
managed logs and metric buffers.

Enhanced resource tables have these keys (resource-module keys remain owned
by that module):

| Keys | Behavior |
|------+----------|
| =g= | Async refresh, suppress stale responses |
| =m u M U= | Mark / unmark / mark visible / clear all marks |
| =/= / =+= | Literal client filter / show all retained rows |
| =RET= / =d= / =y= | Show configured YAML/JSON / describe / copy popup |
| =l= / =e= | Follow selected pod or supported workload / RE2 error logs |
| =p= / =N= | Pod metrics for current list scope / node metrics for context |
| =h= / =R= | Rollout history / confirmed restart (supported workloads) |
| =f= / =F= | Forward selected pod/service/deployment / list forwards |
| =v= / =!= | Pod vterm / prompted non-TTY exec with container discovery |
| =D= / =x= | Confirmed selected / marked deletion |
| =L= / =b= / =?= | Server label selector / buffer chooser / menu |

Direct action keys validate their target or request a target. The menu hides
row actions on headers and hides pod/rollout/log/Strimzi actions for unsupported
selected types. Menu keys are unique: =r c n b g= navigate/refresh;
=/ L a p N C= enhanced filtering/auto-refresh/metrics/CRD metadata;
=RET d y l e h R f D= selected actions;
=v s ! i P S= pod terminal/exec/init logs and Strimzi pause/resume;
=F o H= forwards/output format/action history; =k t E= log stop/follow/filter;
=q= closes the menu, =Q= disables integration. Menu =g= dispatches to the
current native list, enhanced list, metrics, logs, forwards or rollout buffer.

Logs retain their own =g= restart, =s= stop, =c= clear, =F= follow-at-end,
=f= live Go/RE2 filter and =o= Emacs-regexp occur keys. Metrics use =g= refresh.
Port-forward and rollout buffers retain their module keymaps.

* Scope and workflows

=kubed-ext-list-resources= accepts type, context, namespace and selector.
Nil namespace means all namespaces for namespaced enhanced resources; native
Kubed's nil namespace semantics are not changed. A missing context resolves
asynchronously once using Kubed's valid configured/cached default, then
kubeconfig current context. Row operations resolve the default namespace.
Output, logs, metrics, exec and terminal buffers retain the captured execution
environment. Headers show only bounded scope labels, never environment plists.
=kubed-ext-production-context-pattern= highlights matching contexts with a
production warning. Fully-qualified CRD types
work even when metadata discovery is denied. CRDs use compact discovery and
validated environment/context-specific caches, not downloaded OpenAPI schemas
or evaluated resource definitions. Secret list views use server tables;
YAML/JSON Secret-value retrieval is deliberately rejected.

=kubed-ext-switch-context= and =kubed-ext-switch-namespace= preserve the current
resource and selector. Resource switching uses the resource module's completion
and opens an enhanced table. Convenience =kubed-ext-jump-*= commands retain
scope. Enhanced marks/filter/sort and identities stay buffer-local. Namespaced
rows always use a stable =namespace/name= identity, including scoped refreshes
whose server table omits =NAMESPACE=; cluster-scoped rows use their bare name.
Rendered rows are capped at =kubed-ext-resource-display-limit= (1000 by
default), with explicit =+= expansion up to =kubed-ext-resource-retain-limit=
(5000). Parsing runs in 100-row idle batches. A cold CRD namespace view filters
matching rows before the retention cap, so later target rows are not hidden by
unrelated namespaces. Truncated datasets report the retention limit; narrow the
namespace or selector for more rows. Auto-refresh is buffer-local
and opt-in. Finite requests cap combined stdout/stderr at
=kubed-ext-request-byte-limit= (8 MiB); oversized responses fail visibly.
Metrics datasets cap each endpoint at 10000 items; node budgets aggregate in
one pass instead of rescanning all pods per node.

The action module owns describe/show/copy, deletion, rollout history/revision/
undo/restart, Strimzi actions and IPv6-first (=::1=) forwards. Mutations require
explicit context and confirmation. =kubed-ext-jab-deployment= now delegates to
a confirmed rollout restart. The entry point does not overwrite module commands.

=kubed-ext-toggle-output-format= and =kubed-ext-set-output-format= affect the
*next* resource display, not a previously opened output buffer.
=kubed-ext-switch-buffer= chooses live native/enhanced workflows.
=kubed-ext-show-command-log= shows up to 100 explicit action-module commands,
shell-quoted for copying. It is not a global audit: discovery, logs, exec,
forwards and copy-only requests are not all recorded. No generic process advice
is installed. Commands can include sensitive patch arguments; treat history as
sensitive and clear =kubed-ext--command-history= when appropriate.

* Stern and terminals

Selected targets are exact Stern queries; a chosen container uses an exact
RE2 expression. Workload logs keep their actual resource type. Live filters
use Go RE2, not Emacs regexp syntax. =occur= is a separate Emacs-regexp operation.
Snapshot mode uses =--no-follow=; follow mode omits it. Unsupported limit or
absolute-since options and missing Stern fall back to basic upstream Kubed logs
where supported. Advanced Stern-only commands require Stern.

The upstream-compatible =since= argument is absolute (=--since-time=), not a
Stern duration; any non-nil value uses upstream fallback. A legacy nil =since=
also uses upstream Kubed so it retains its no-cutoff semantics instead of
silently inheriting Stern's 48-hour default. Native Stern specifications omit
=:since= to request their explicit one-hour Stern default. Nil =tail= remains
nil. Snapshot plus tail zero is rejected because Stern does not support that
combination; follow plus tail zero is valid.

Managed logs stop on kill/restart/major-mode change, suppress replaced-process output and bound
retention with =kubed-ext-log-retention-characters=. Pod terminal commands use
asynchronous container discovery; session labels include context/namespace/
pod/container. Noninteractive exec accepts argv and does not request a TTY.
Eshell starts in the resolved Kubed TRAMP pod/container directory; it does not
send an interactive =exec -it= subprocess. Terminal and metrics cleanup also
runs before a major-mode change. Dead forwarding sessions are removed from
the registry rather than retaining launch environments as history.

* Disable and migration

=kubed-ext-setup= makes no cluster requests. =kubed-ext-disable= and the entry
unload hook stop owned transport, resource timers/discovery, logs, terminals,
port forwards and metrics callbacks. Modules stay loaded because globally
unloading shared dependencies could invalidate unrelated consumers. Buffers
remain available for inspection; new explicit commands can start work again.
Run setup to reinstall entry keys/advice after disable.

Bindings are restored only when the actual keymap still contains the command
installed by this entry point. Later user edits survive; module-defined base
keymaps remain. The only advice is narrow explicit-action history advice,
removed on disable. No =kubed-update= override, global CRD column mutation,
CRD-derived eval, generic process advice or global TRAMP tuning is installed.

The original =HEAD:kubed-ext.el= exports were audited, not assumed private.
Some public wide-list, numeric, prefetch, process-buffer and circuit-breaker
helpers are still absent. These gaps and intentionally retired global internals
are listed separately in the verification report.
